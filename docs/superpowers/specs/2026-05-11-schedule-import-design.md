# 导入已有课表 - 设计文档

## 概述

排课管理页面新增“上传已有课表”能力，支持用户上传图片课表或 Excel 课表。系统识别课表内容后，不直接覆盖正式课表，而是生成待确认草案。教务老师核对并发布草案后，正式课表才会变更。

本设计服务于第一版落地，目标是把“已有课表导入”这条链路打通：上传已有课表、识别科目、自动匹配教师、人工修正异常、生成待确认草案、二次确认发布。

## 已确认决策

- 导入结果默认生成待确认草案，不直接导入正式课表。
- 支持年级总课表和单班课表两种上传范围。
- 如果本年级已有正式课表，上传新课表前弹窗确认。
- 上传确认只代表开始识别，不代表覆盖正式课表。
- 核对完成后，用户点击“生成待确认草案”，界面必须明确提示正式课表尚未变更。
- 发布草案时再二次确认，发布后才替换正式课表。
- 用户上传的课表可能只有科目，没有教师；系统需要根据后端年级、班级、科目、教师数据自动匹配任课教师。
- 核对页支持逐格修改科目和教师，并标记无法识别或无法匹配的课位。

## 用户流程

1. 学校管理员进入排课管理页面，选择年级。
2. 点击顶部快速操作区的“上传已有课表”。
3. 如果该年级已有正式课表，系统弹窗提示：上传新课表只会生成待确认草案，不会立即覆盖正式课表。
4. 用户选择导入范围：年级总课表或单班课表。
5. 用户上传图片或 Excel 文件。
6. 后端创建导入任务，识别文件内容，并根据系统任课安排匹配教师。
7. 前端展示识别核对页。
8. 用户修正未识别科目、未匹配教师、多候选教师等异常。
9. 用户点击“生成待确认草案”。
10. 系统提示“已生成待确认草案，正式课表尚未变更”。
11. 用户查看草案，确认后点击“发布为正式课表”。
12. 如果发布会替换现有正式课表，系统二次确认。
13. 发布成功后，教师和学生端看到新的正式课表。

## 前端设计

### 排课管理页入口

在当前 `ScheduleManage.jsx` 的顶部快速操作区新增 `上传已有课表` 按钮。

- 按钮图标使用上传或文件类图标，例如 `UploadOutlined` 或 `FileExcelOutlined`。
- 按钮视觉层级低于 `开始自动排课`。
- 未选择年级时，按钮禁用或点击提示 `请先选择年级`。
- 点击按钮后打开独立弹窗向导，不把导入流程塞进自动排课配置标签页。

### 导入弹窗向导

桌面端使用宽弹窗，移动端使用全屏 Drawer。向导包含固定步骤条：

```text
选择范围 -> 上传文件 -> 识别核对 -> 生成草案
```

弹窗顶部说明：

```text
识别结果会先生成待确认草案，不会直接覆盖正式课表。
```

底部固定操作栏：

- 上一步
- 重新上传
- 下一步
- 生成待确认草案

### 选择范围

使用分段控件选择：

- 年级总课表
- 单班课表

年级总课表使用当前已选年级。单班课表需要额外选择班级。

### 上传文件

上传区支持拖拽和点击选择文件。

支持格式：

- 图片：`jpg`、`jpeg`、`png`
- Excel：`xlsx`、`xls`

上传区说明两类来源：

- 图片课表：适合纸质课表拍照或截图。
- Excel 课表：适合电子表格课表。

### 识别核对页

核对页的核心目标是让教务老师快速发现问题并修正。

顶部摘要卡片展示：

- 总课位
- 待确认
- 未匹配教师
- 已修改

桌面端使用课表网格：

- 行：节次
- 列：星期
- 年级总课表时，上方使用班级 Tabs。
- 单班课表时，直接展示该班课表。

移动端优先展示异常列表，用户点击异常后进入对应课位编辑。

单元格状态：

- 正常：显示科目和教师。
- 识别待确认：科目或课位识别置信度较低。
- 未识别科目：必须修正后才能生成草案。
- 教师待确认：系统匹配到多个候选教师。
- 未匹配教师：系统找不到对应教师。
- 已修改：用户手动修正过。

单元格展示示例：

```text
数学
王老师
```

未匹配教师时：

```text
数学
未匹配教师
```

多个候选教师时：

```text
数学
教师待确认
```

### 单元格编辑

桌面端使用右侧 Drawer 或浮层编辑。字段包括：

- 科目
- 教师
- 匹配来源
- 候选教师
- 备注

操作包括：

- 保存
- 保存并下一个
- 清空课位
- 标记为空课

第一版不提供拖拽调课、批量替换、增删节次等完整课表编辑器能力。

### 草案生成反馈

用户点击“生成待确认草案”后，成功页必须明确提示：

```text
已生成待确认草案，正式课表尚未变更。
```

页面展示两个主要动作：

- 查看草案
- 发布为正式课表

如果该年级已有正式课表，额外展示警示：

```text
发布后将替换当前年级正式课表。
```

正式课表预览区仍展示旧正式课表，导入草案单独展示，避免用户误以为上传已经生效。

### 现有草案区兼容

当前排课管理页已有“当前任务与草案”区域。该区域需要区分草案来源：

- 自动排课生成
- 上传课表识别生成

导入草案可以复用草案发布能力，但文案必须强调其来源和待确认状态。

## 后端设计

### API 草案

新增导入任务接口：

```text
POST /api/schedule/imports
GET /api/schedule/imports/{import_id}
GET /api/schedule/imports/{import_id}/items
PATCH /api/schedule/imports/{import_id}/items/{item_id}
POST /api/schedule/imports/{import_id}/draft
```

发布草案复用或扩展现有接口：

```text
POST /api/schedule/drafts/{draft_id}/publish
```

### 创建导入任务

`POST /api/schedule/imports` 接收：

- `grade`
- `import_scope`: `grade` 或 `class`
- `class_id`: 单班课表时必填
- `file_type`: `image` 或 `excel`
- `file`

后端创建导入任务后进入 `pending` 或 `processing` 状态。

### 导入任务状态

任务状态建议：

- `pending`
- `processing`
- `needs_review`
- `failed`
- `draft_created`

任务响应示例：

```json
{
  "id": 12,
  "grade": "七年级",
  "scope": "grade",
  "class_id": null,
  "status": "needs_review",
  "source_type": "excel",
  "has_existing_published_timetable": true,
  "summary": {
    "total_slots": 240,
    "recognized_slots": 232,
    "unrecognized_subject_slots": 2,
    "teacher_unmatched_slots": 3,
    "teacher_ambiguous_slots": 5,
    "manually_fixed_slots": 4
  }
}
```

### 导入课位结构

课位 item 响应示例：

```json
{
  "id": 101,
  "class_id": 3,
  "weekday": 1,
  "period_id": 2,
  "subject_id": 8,
  "recognized_subject_name": "数学",
  "teacher_id": 15,
  "teacher_match_status": "matched",
  "teacher_match_source": "teaching_arrangement",
  "teacher_candidates": [],
  "confidence": 0.92,
  "issue_flags": []
}
```

### 教师匹配规则

如果文件中包含教师信息，优先使用文件中的教师，并尝试匹配系统教师账号。

如果文件中没有教师，或教师识别为空，后端根据系统数据自动匹配：

1. 文件中明确识别到教师，且能匹配系统教师账号。
2. 后端已有班级、科目、教师任课安排。
3. 如果一个班级某科只有一个候选教师，自动填入。
4. 如果存在多个候选教师，标记为 `teacher_ambiguous`。
5. 如果没有候选教师，标记为 `teacher_unmatched`。

匹配来源字段建议：

- `file_recognition`
- `teaching_arrangement`
- `single_candidate`
- `manual`
- `unmatched`

### 生成草案校验

生成待确认草案前，后端再次校验：

- 班级存在。
- 星期和节次有效。
- 科目已匹配系统科目。
- 必需的教师已匹配。
- 没有未识别科目。
- 没有未匹配教师。

如果仍有教师多候选项，第一版建议要求用户确认后再生成草案。

## 覆盖和权限规则

### 权限

第一版仅允许 `school_admin` 执行：

- 上传已有课表
- 生成导入草案
- 发布正式课表

教师和学生只查看已发布课表。

### 已有正式课表保护

选择年级后，前端需要知道该年级是否已有正式课表。

如果已有，上传前提示：

```text
当前年级已有正式课表。上传新课表只会生成待确认草案，不会立即覆盖正式课表。是否继续？
```

生成草案后提示：

```text
已生成待确认草案，正式课表尚未变更。
```

发布草案时提示：

```text
发布后将替换当前年级正式课表。此操作会影响教师和学生查看，是否继续？
```

## 异常处理

- 文件格式不支持：阻止上传，提示支持格式。
- 图片识别失败：任务进入 `failed`，允许重新上传。
- Excel 表格不规范：尽量解析；无法定位班级、星期、节次时提示用户选择映射或重新上传。
- 科目无法识别：必须修正后才能生成草案。
- 教师无法匹配：必须选择教师后才能生成草案。
- 多候选教师：标记为教师待确认，用户确认后才能生成草案。
- 与现有正式课表冲突：只在草案层展示，不直接覆盖正式数据。

## 第一版不做

- 直接上传后覆盖正式课表。
- 拖拽调课。
- 批量替换教师或科目。
- 多版本课表历史对比。
- 任意复杂 Excel 模板映射器。
- OCR 置信度模型可视化。
- 教师无课、冲突约束的高级求解。

## 验收标准

- 学校管理员能在排课管理页打开“上传已有课表”向导。
- 用户能选择年级总课表或单班课表。
- 本年级已有正式课表时，上传前有明确确认弹窗。
- 图片和 Excel 上传入口都清晰可见。
- 识别结果可以展示为待核对课表。
- 文件中没有教师时，系统能根据后端任课安排匹配教师。
- 未识别科目、未匹配教师、多候选教师能在核对页被清楚标记。
- 用户能逐格修正科目和教师。
- 有未识别科目或未匹配教师时，不能生成草案。
- 用户点击生成后，界面明确提示“已生成待确认草案，正式课表尚未变更”。
- 发布草案前有二次确认，发布后才替换正式课表。
- 教师和学生端只看到已发布课表，不看到导入中的草案。
