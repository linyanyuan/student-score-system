# 教师管理工作台重设计说明

## 1. 背景

当前教师管理页面 [`frontend/src/pages/TeacherClassManage.jsx`](d:/project/student-score-system/frontend/src/pages/TeacherClassManage.jsx) 已具备完整业务能力，包括：

- 教师与班级绑定
- 教师-科目-班级分配
- 班级-科目-教师矩阵查看
- 按教师-科目聚合的分配汇总与删除

但它仍然主要停留在旧式后台工具页结构，整体以 `Card + 表单 + Table` 直接堆叠为主，和当前已完成 workspace 化升级的页面存在明显落差，尤其是：

- [`frontend/src/pages/Home.jsx`](d:/project/student-score-system/frontend/src/pages/Home.jsx) 已使用工作台式首屏摘要、指标卡和分区工作区
- [`frontend/src/pages/SubjectManage.jsx`](d:/project/student-score-system/frontend/src/pages/SubjectManage.jsx) 已使用统一的 `WorkspacePageHeader`、`WorkspaceMetricCard`、`WorkspaceSectionCard`
- [`frontend/src/components/workspace/WorkspacePageHeader.jsx`](d:/project/student-score-system/frontend/src/components/workspace/WorkspacePageHeader.jsx) 等基础组件已经形成稳定设计语言

本次工作目标是在不改动现有接口和核心业务规则的前提下，将教师管理重构为与首页、科目管理一致的 workspace 工作台页面，同时强化首屏分配效率。

## 2. 目标与非目标

### 2.1 目标

- 将教师管理改造成统一的 workspace 工作台页面
- 保持“总览 + 主流程优先”的双重平衡布局
- 提升教师选择、班级绑定、科目分配的操作连续性
- 保留矩阵视图与分配汇总能力，但提升信息层级和可读性
- 沿用现有蓝色 workspace 视觉体系，仅以琥珀色强调提醒态
- 在不改变接口的前提下，通过前端派生数据补充指标卡和上下文提示

### 2.2 非目标

- 不新增或修改后端接口
- 不改变教师绑定、科目分配、覆盖确认、删除分配等业务语义
- 不改变菜单路由、权限模型或页面入口
- 不将教师管理拆分成新的多页面流程
- 不引入与现有系统不一致的全新视觉体系

## 3. 用户确认的设计方向

本次设计已经过用户确认，方向为：

- 页面定位：教师管理工作台
- 布局策略：顶部总览 + 首屏主流程优先
- 功能边界：只重做前端展示与交互层次，保留现有功能和接口不变
- 方案选择：采用“三种布局方案”中的 `C. 双重平衡型`

这意味着页面需要同时满足两类诉求：

- 管理视角：快速感知覆盖情况、异常提醒、当前配置完整度
- 操作视角：在首屏直接完成教师选择、班级绑定和科目分配

## 4. UI/UX 设计结论

本次设计结合 `ui-ux-pro-max` 搜索结果进行收敛，核心结论如下：

- 页面模式：`Data-Dense + Drill-Down`
- 风格方向：高信息密度工作台，但保持轻量、清晰、可读
- 配色策略：蓝色为主、琥珀色为提醒强调、背景维持浅色 workspace 氛围
- 交互重点：首屏放置主流程，提醒信息作为上下文辅助而非主视觉中心
- 可用性重点：减少用户在不同表单区块之间跳跃，减少无关选项干扰，保留清晰的覆盖确认

不采用的方向包括：

- 纯驾驶舱式运营大盘
- 只强调表单效率、弱化全局感知的极简工具页
- 强装饰性或重动效方案
- 偏紫色或深色的数据面板风格

## 5. 信息架构

页面整体从上到下分为四层。

### 5.1 页面头部摘要层

使用 `WorkspacePageHeader` 承载页面定位信息：

- eyebrow：`Teacher Workspace`
- 标题：`教师管理工作台`
- 描述：强调“围绕教师绑定、授课分配和覆盖提醒组织教师管理工作区”
- 右侧主操作：保留在首屏可见，但不新增业务动作；可根据实现选择仅展示说明性 meta，而不是额外按钮

Header 内部展示四张指标卡：

- 教师总数
- 已绑定班级数
- 已分配科目组数
- 待补齐项数

其中“待补齐项”使用琥珀色强调，用于提示：

- 未绑定班级的教师
- 已绑定但尚未分配科目的教师
- 当前存在潜在覆盖关注项的配置状态

### 5.2 首屏主流程层

首屏核心区域采用左右双栏：

- 左侧宽栏：主流程工作区
- 右侧窄栏：当前教师上下文与待处理提醒

左侧主流程工作区按任务顺序组织为连续三段：

1. 选择教师
2. 绑定班级
3. 分配科目

要求这三段在视觉上属于同一工作区，而不是三个彼此割裂的小页面，用户选中教师后能立即连续完成后续动作。

### 5.3 结果展示层

首屏之后保留两块结果区域：

- 班级-科目-教师矩阵
- 分配汇总（按教师-科目聚合）

这两块改造成统一的 `WorkspaceSectionCard` 结构，使其定位更明确：

- 矩阵更偏覆盖总览
- 汇总更偏结果清单与回查操作

### 5.4 页面节奏

页面阅读节奏调整为：

`Header 摘要` -> `主流程 + 提醒` -> `矩阵总览` -> `分配汇总`

这样既符合工作台页面的首屏逻辑，也避免旧版页面中“提示、表单、表格彼此抢占注意力”的问题。

## 6. 交互设计

### 6.1 教师选择

- 选择教师作为整个工作流的起点
- 未选教师时，绑定和分配区块以引导态展示
- 选中教师后，右侧上下文卡即时刷新该教师的当前状态

需要在状态摘要中展示：

- 已绑定班级数
- 已分配科目组数
- 涉及年级范围
- 是否存在待补齐项

### 6.2 班级绑定

- “绑定班级”维持多选逻辑不变
- 已绑定班级列表保留解除绑定操作
- 新增绑定区与已绑定列表应放在同一段工作区内，便于用户理解“服务范围建立”这一动作

交互目标是让用户先明确教师的服务班级范围，再进入科目分配，而不是在页面不同位置来回切换。

### 6.3 科目分配

- 仅在已选教师上下文中展示
- 科目选项继续基于所选班级年级范围过滤
- 分配动作保留现有批量班级分配能力

若出现以下场景，继续使用现有确认机制，但在视觉层级上前置提醒：

- 该教师已有同科目分配
- 目标班级已有该科目对应的其他教师

提醒方式应优先考虑在操作区上方或右侧上下文区展示 `Alert`/状态提示，而不是只在点击提交后突然进入确认。

### 6.4 矩阵视图

- 保留按年级筛选
- 保留表格型矩阵结构
- 在视觉上强化“总览”感，而不是把它呈现为普通数据表

矩阵区的主要目标是帮助管理者快速回答两个问题：

- 某个年级下哪些班级已经完成主要科目分配
- 某个科目在不同班级上的授课教师是谁

### 6.5 分配汇总

- 继续按教师-科目聚合
- 继续保留整组删除能力
- 更强调“结果回查”和“批量撤销”语义

汇总表应与矩阵区形成区分：

- 矩阵回答“覆盖情况”
- 汇总回答“谁给哪些班级上什么课”

## 7. 视觉设计

### 7.1 视觉语言

整体视觉语言延续现有 workspace 系统：

- 浅色渐变背景
- 柔和卡片边框与阴影
- 清晰的标题层级
- 信息密度较高但不拥挤

教师管理不应另起一套视觉主题，而应成为“首页、科目管理、班级管理”体系内的同类页面。

### 7.2 色彩

采用与现有页面一致的综合色彩策略：

- 主色：蓝色，用于标题、主按钮、主信息强调
- 提醒色：琥珀色，用于待补齐项、关注项、覆盖提醒
- 成功态：绿色
- 危险态：红色
- 中性文本：复用 `--workspace-ink`、`--workspace-muted`

### 7.3 卡片与层级

- Header 摘要区与 Section 卡片均复用现有 workspace 卡片体系
- 主流程区视觉上更强，但不通过夸张颜色吸引注意，而通过布局优先级和占比实现
- 右侧提醒卡做轻强调，不抢主流程主体地位

### 7.4 表格与状态

- 表格继续使用 Ant Design `Table`
- 保证移动端和窄屏下至少具备横向滚动，不允许直接撑破视口
- 行 hover、Tag、空状态、Alert 语气与现有 workspace 页面统一

## 8. 技术实现边界

### 8.1 保持不变的部分

- 所有 API 调用及参数结构
- `createTeacherClass` / `deleteTeacherClass`
- `createTeacherSubjectAssignments` / `deleteTeacherSubjectAssignment`
- `getTeacherClasses` / `getTeacherSubjectAssignments`
- 已有覆盖确认逻辑与分配规则
- 矩阵数据和汇总数据的核心派生方式

### 8.2 允许调整的部分

- 页面整体 DOM 结构
- 各业务块的摆放顺序
- 局部派生指标与提醒文案
- 复用和扩展 workspace 基础组件
- 适量新增教师管理专属样式类

### 8.3 组件组织建议

[`frontend/src/pages/TeacherClassManage.jsx`](d:/project/student-score-system/frontend/src/pages/TeacherClassManage.jsx) 作为页面入口，负责：

- 数据请求
- 页面级派生数据
- 主流程状态
- 各 section 的组装

若文件复杂度继续增长，允许将以下片段抽为同目录局部组件或 helper：

- 指标卡派生
- 当前教师上下文摘要
- 主流程工作区
- 矩阵区
- 汇总区

原则是局部组件只服务当前页面，不做无边界抽象。

## 9. 验证策略

### 9.1 结构验证

- 页面必须进入 `workspace-page` 结构
- 页面标题与文案应明确体现“教师管理工作台”
- 首屏应先出现总览指标和主流程区，再出现矩阵与汇总区

### 9.2 功能回归

- 教师切换后仍能刷新已绑定班级
- 班级绑定与解绑行为不回归
- 科目过滤逻辑不回归
- 覆盖确认逻辑不回归
- 整组删除分配不回归

### 9.3 交互与响应式

- 窄屏下表格保持可滚动
- 空状态与提醒文案清晰
- 颜色不是唯一状态表达方式
- 焦点和 hover 状态可见

### 9.4 测试补充

至少补充或更新一项围绕页面 workspace 化内容的前端结构测试，验证：

- 页面使用工作台结构
- 教师管理文案与主流程分区存在
- 结果区顺序符合设计意图

## 10. 实施顺序

建议按以下顺序实现：

1. 将页面外层改造成 workspace 结构
2. 增加 Header 摘要与指标卡
3. 重组首屏主流程与右侧提醒区
4. 重组矩阵与汇总区的 section 容器
5. 补充教师管理专属样式与响应式细节
6. 更新或新增相关测试并执行验证

## 11. 结论

本次重设计不是为教师管理单纯“换皮”，而是把它正式纳入当前系统已经建立的 workspace 工作台体系。

最终页面应同时满足两个核心目标：

- 让学校管理员先看清当前教师配置的整体状态
- 让高频的教师绑定与科目分配在首屏顺畅完成

在此基础上，矩阵和汇总作为结果层继续承接管理视角，既保持功能完整，又显著改善页面层级、可读性和操作节奏。
