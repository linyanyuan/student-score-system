# 考试年级科目与成绩管理流程设计

## 背景

当前考试管理仅支持为一场考试选择参与年级，无法配置“某个参与年级在这场考试中实际考试的科目”。成绩管理因此存在多个问题：

- 录入成绩会展示全量科目，无法按学生所在年级和考试配置裁剪。
- 编辑成绩时会回落到全部科目，而不是当前列表表头对应科目。
- 批量导入需要在主页面上先选导入年级，交互割裂。
- 导出 Excel 会输出所有科目，而不是学生所在年级在该考试中的实际科目。

## 目标

- 为考试管理补齐“考试 -> 年级 -> 科目”的完整配置能力。
- 成绩录入、编辑、导入、导出统一基于“该学生所在年级在该考试中的实际科目”运行。
- 导出 Excel 按年级拆分工作表，每个工作表仅包含该年级在该考试中的科目列。

## 数据模型

保留考试表中的 `grade` 字段，用逗号分隔文本表示参与考试的年级集合，以兼容现有筛选和分析逻辑。

新增考试年级科目关联表：

- 表名：`exam_grade_subjects`
- 字段：
  - `id`
  - `exam_id`
  - `grade`
  - `subject_id`
- 约束：
  - `exam_id + grade + subject_id` 唯一

该表表达“某场考试中，某个年级实际参加考试的某个科目”。

## 接口设计

### 考试管理

考试创建与编辑接口除保存考试基础信息外，还保存 `grade_subjects` 结构化数据。请求和响应都返回按年级分组后的科目配置，避免前端自行拼装。

后端校验规则：

- 只能为已选中的参与年级配置科目。
- 每个参与年级至少配置一个科目。
- 科目必须存在。
- 科目必须适用于对应年级。
- 更新考试时，新的年级科目集合会替换旧集合，移除无效关联。

### 成绩管理

新增“考试 + 学生 -> 可录入科目”接口，后端根据学生班级推导年级，再根据考试年级科目关联返回排序后的科目列表。

成绩录入与更新接口新增约束：

- 学生所属年级必须在该考试参与年级内。
- 科目必须在该考试该年级配置的科目集合内。

批量导入只识别当前导入年级在该考试中配置的科目；不在配置中的科目列视为不合法输入。

导出 Excel 时按年级拆分 sheet；每个 sheet 只包含该年级在该考试中的科目列和该年级学生数据。

## 前端交互

### 考试管理页

- 新建/编辑考试时，保留“参与年级”多选。
- 选中年级后，弹窗中动态展示每个年级的“考试科目”多选区域。
- 每个年级仅展示适用于该年级的科目候选。
- 取消某个年级时清理其已选科目。
- 考试列表直接展示“年级 -> 科目”摘要。

### 成绩管理页

- 点击“录入成绩”后先展示学生搜索与选择。
- 仅当用户选择学生后，才请求并展示该学生在该考试中的可录入科目。
- 编辑成绩时使用当前表格表头对应的科目集合，而不是全部科目。
- 批量导入改为按钮打开弹窗，在弹窗内先选择导入年级，再上传文件。
- 导出 Excel 沿用当前考试和班级筛选条件，但输出按年级拆 sheet。

## 测试策略

后端优先补充 API/行为测试，覆盖：

- 考试创建和更新时的年级科目关联保存与替换
- 学生可录入科目接口
- 非考试配置科目的成绩录入拒绝
- 导出 Excel 按年级拆分 sheet 且列正确

前端补充回归测试，覆盖：

- 考试管理页包含按年级配置考试科目的结构与文案
- 成绩录入流程先搜学生后显示科目
- 批量导入弹窗内选择导入年级
- 编辑成绩使用当前表头科目
