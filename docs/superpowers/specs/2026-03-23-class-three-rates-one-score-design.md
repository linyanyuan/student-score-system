# 班级分析三率一分设计

## 需求摘要
在“班级成绩分析”页面，选中班级后，在“成绩分布”卡片下方新增“三率一分”模块。
模块按科目展示 4 个指标：
- 优秀率分数
- 良好率分数
- 及格率分数
- 平均分

## 计算规则
1. 在同一场考试内、按当前用户可见班级范围，逐科统计每个班的达标人数：
- 优秀人数：分数 >= 科目总分 * 90%
- 良好人数：分数 >= 科目总分 * 70%
- 及格人数：分数 >= 科目总分 * 60%
2. 对每个科目，取“达标人数最多”的班级为 100 分。
3. 当前班该科对应指标分数 = 当前班达标人数 / 该科达标人数最大值 * 100。
4. 平均分 = 当前班该科平均分。

## 关键实现决策
### 方案对比
1. 新增独立接口（推荐）
- 优点：职责清晰；不破坏现有分布接口响应结构；前端一次请求即可拿到三率一分结果。
- 缺点：新增一个后端接口与一个前端 API 封装。

2. 复用现有接口在前端拼装
- 优点：后端改动少。
- 缺点：需要多次请求且缺少“各班达标人数”原始数据，无法准确计算三率分数。

3. 扩展现有 distribution 接口
- 优点：接口数量不增加。
- 缺点：接口语义变重，历史依赖风险更高。

结论：采用方案 1。

### 科目总分来源
当前数据模型无“科目满分”字段。为保证规则可落地，采用如下推导：
- 科目总分 = 当前考试、当前可见范围内该科最高分。
该策略与现有总分分布使用“样本最大值作为阈值基准”的实现思路保持一致。

## 接口设计
新增：`GET /api/analysis/class/{class_id}/exam/{exam_id}/three-rates-one-score`

返回示例：
```json
[
  {
    "subject_id": 1,
    "subject_name": "语文",
    "excellent_rate_score": 83.33,
    "good_rate_score": 90.91,
    "pass_rate_score": 100.0,
    "avg_score": 86.25
  }
]
```

## 前端展示设计
在 `ClassAnalysis.jsx` 的“成绩分布”卡片下新增卡片“科目三率一分”。
表格列：科目、优秀率分数、良好率分数、及格率分数、平均分。
分数保留 2 位小数。

## 权限与范围
复用现有班级分析权限：
- 学生：禁止访问
- 教师：按考试年级可见班级范围
- 管理员：按既有可见范围

## 测试策略
- 先写后端纯函数单测（RED）：验证三率阈值计数与“按最大值归一到 100 分”逻辑。
- 再补接口实现（GREEN）：跑新增测试与既有测试文件。
- 前端构建校验：确保新增 UI 不破坏编译。
