# 移动端课表菜单与节次同步设计

## 目标
统一 web 和移动端的节次时间口径，移除课表页右上角按钮，并把左上角入口改成轻量菜单，提供 `备忘录` 和 `我的概览` 两个高频功能。

## 现状
- 移动端课表页仍有本地 `periodId -> 时间` 兜底映射，和后端真实节次不一致时会显示错位时间。
- 课间分隔线目前只按 `periodId` 区间判断，固定展示 `课间休息 (20M)`，不是按真实时间差计算。
- 后端课表接口已经返回 `period_start_time` / `period_end_time`，这应是唯一时间来源。
- web 端已有备忘录接口和页面逻辑，移动端可以直接复用同一组后端 API。
- `我的概览` 目前没有现成聚合接口，需要后端补一层角色化汇总数据。

## 方案
### 方案 A: 轻量菜单 + 统一后端节次口径（推荐）
- 左上角按钮打开底部菜单。
- 菜单只放 `备忘录` 和 `我的概览`。
- 课表时间完全依赖后端节次数据，不再用本地固定时间表兜底。
- 课间休息按真实相邻节次的时间差计算。

### 方案 B: 左上角做成多功能抽屉
- 把更多入口也塞进同一个菜单。
- 信息更全，但会和底部导航、个人页功能重叠。

### 方案 C: 保留当前右上角刷新/筛选按钮
- 改动最小，但不解决“菜单入口”诉求，也会继续显得杂乱。

结论：采用方案 A。

## 交互设计
### 课表页头部
- 只保留左上角菜单按钮。
- 右上角按钮去掉。
- 刷新通过下拉刷新完成，不再放在标题栏。

### 左上角菜单
- `备忘录`
  - 进入移动端备忘录页。
  - 数据源直接复用 web 端同一套 `/api/memos`。
  - 以待办/进行中事项为主，支持新增、编辑、完成切换。
- `我的概览`
  - 进入概览页或底部面板。
  - 教师：教了几个班、共有多少学生、每个班最近考试平均分。
  - 学校管理员：共有几个班、共有多少学生、各年级最近考试的年级平均分。
  - 这块使用单独的聚合接口，避免前端自己拼表。

## 数据设计
### 节次同步
- web 和移动端都只认后端 `schedule_periods`。
- 移动端课表项直接使用接口返回的 `period_start_time` / `period_end_time`。
- 如果某条课表缺少时间字段，不再回退到本地固定时刻表，而是显示缺失状态。

### 课间休息
- 只在真实存在时间间隔时插入。
- 文案由实际分钟数计算，不固定写死 `20M`。
- 如果后端节次已连续衔接，则不显示休息分隔。

### 我的概览接口
- 建议新增一个角色自适应的汇总接口。
- 返回内容按角色分支，但前端只调用一个入口。
- 教师侧重点是“班级维度”。
- 学校管理员侧重点是“年级维度”。

## 风险
- 如果继续保留本地兜底时间，web 和 mobile 仍会出现口径漂移。
- 如果概览接口拆得太细，前端会产生多次请求和不一致的统计口径。
- 如果菜单里塞太多功能，会和底部导航、个人中心重复。

## 验证
- 移动端课表显示应与后端节次管理一致。
- 左上角菜单只出现两个入口，右上角不再显示。
- 备忘录数据能直接从现有后端接口读取。
- 概览页按不同角色返回不同汇总数据。
