# 班级分析排行榜与首页节次管理迭代设计

## 目标
基于当前班级分析页面，完成三项迭代：
1. 科目排名改为“单科班级平均分排行榜”，可切换科目。
2. 三率一分改为“按班级展示”的排行榜，默认显示在两张排名图下方，支持按科目切换。
3. 修复 `xiyu` 账户在首页点击“节次管理”无反应问题。

## 需求细化
### 1) 科目排名
- 展示效果与“班级平均分排名”一致（横向排行榜）。
- 使用单选下拉框切换科目。
- 切换科目后刷新该科各班平均分排名。

### 2) 三率一分
- 展示位置：科目排名和班级平均分排名下方。
- 默认进入“班级成绩分析”即显示，不依赖选中某个班级。
- 展示列：班级、优秀率分数、良好率分数、及格率分数、平均分、总分数。
- 总分数 = 优秀率分数 + 良好率分数 + 及格率分数 + 平均分。
- 默认按总分数降序。
- 提供科目下拉，默认第一门科目。
- 下拉不包含“总分”选项。

### 3) 首页节次管理
- 对 school_admin 点击“节次管理”时，始终打开弹窗。
- 当当前无节次数据时，不应无响应；应给出可继续维护的提示/入口。

## 方案选择
### 方案 A：前端多接口拼装（不推荐）
- 前端循环请求多个班级的三率一分，再聚合排序。
- 风险：请求量高、性能差、逻辑分散。

### 方案 B：后端新增“班级维度三率一分排行榜”接口（推荐）
- 后端一次返回“指定考试 + 指定科目”的各班三率一分数据。
- 前端直接渲染和切换科目。
- 优势：性能好、口径一致、后续扩展简单。

### 方案 C：复用 classes/rank 混入新字段（不推荐）
- 破坏接口职责，回归风险高。

结论：采用方案 B。

## 后端设计
### 新增接口
- `GET /api/analysis/exam/{exam_id}/subject/{subject_id}/three-rates-one-score-rank`

### 返回结构
- 数组元素字段：
  - `class_id`
  - `class_name`
  - `excellent_rate_score`
  - `good_rate_score`
  - `pass_rate_score`
  - `avg_score`
  - `total_score`

### 计算口径
- 阈值：优秀 90%，良好 80%，及格 60%。
- 分母：同年级内该科对应达标人数最大值（全年级口径）。
- 满分：沿用当前“学校可配置满分”能力（语文/数学/英语/其他可配置）。
- 排序：按 `total_score` 降序。

## 前端设计
### ClassAnalysis.jsx
- 科目排名区域：
  - 去掉复选框多科分组图。
  - 改为单科下拉 + 横向排行榜。
- 三率一分区域：
  - 从“选中班级后才显示”调整为默认显示。
  - 新增科目下拉，默认第一门科目。
  - 使用后端新接口数据填充表格并按总分数展示。
- 保留“成绩分布/偏科生/后进生”为深度分析（仍需选中班级）。

### Home.jsx
- “节次管理”按钮点击逻辑改为：
  - 有节次：打开当前第一个节次编辑。
  - 无节次：打开弹窗并提示“暂无节次，请先在后端初始化或新增节次”。
  - 至少保证点击有反馈，不再静默失败。

## 测试策略
1. 后端单测：
- 新增班级维度三率一分排行的纯函数/接口逻辑测试。
- 覆盖总分数计算与排序。
2. 前端验证：
- 构建通过。
- 手工检查科目切换、默认显示、节次管理点击行为。

## 风险与兼容
- 旧前端三率一分数据结构与新接口不兼容，需要同步替换调用。
- 若部分学校无满分配置，使用默认配置兜底，保证可用。
