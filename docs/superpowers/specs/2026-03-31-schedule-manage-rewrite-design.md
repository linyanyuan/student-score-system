# 排课管理页重写设计说明

## 1. 背景

当前 [`frontend/src/pages/ScheduleManage.jsx`](d:/project/student-score-system/frontend/src/pages/ScheduleManage.jsx) 已出现明显乱码、内容截断和交互失稳问题，已经不适合作为继续迭代的基础。

本次工作范围明确限定为：

- 只重写前端排课管理页 [`frontend/src/pages/ScheduleManage.jsx`](d:/project/student-score-system/frontend/src/pages/ScheduleManage.jsx)
- 沿用现有后端排课接口与数据结构，不在本轮改动后端求解引擎
- 以“快速配置排课参数”为首要目标，而不是先优化草案审查工作流

## 2. 现状确认

仓库内已经存在可复用的排课后端能力：

- `GET/POST /api/schedule/lesson-plan`
- `GET/POST /api/schedule/teaching-arrangement`
- `GET/POST /api/schedule/lesson-plan-overrides`
- `GET/POST /api/schedule/teacher-constraints`
- `GET/POST /api/schedule/locks`
- `POST /api/schedule/drafts/{grade}/solve`
- `GET /api/schedule/tasks/{task_id}`
- `GET /api/schedule/drafts/{draft_id}`
- `GET /api/schedule/drafts/{draft_id}/items`
- `POST /api/schedule/drafts/{draft_id}/publish`
- `GET /api/timetable/class/{class_id}`

对应前端 API 封装已存在于 [`frontend/src/api/scheduling.js`](d:/project/student-score-system/frontend/src/api/scheduling.js)。

因此，本次页面重写属于“恢复并重建稳定前端工作台”，不是重新定义后端排课协议。

## 3. 目标与非目标

### 3.1 目标

- 让学校管理员能在一个页面内高效完成排课参数录入和修改
- 降低不同配置模块之间来回切换的成本
- 保留排课任务、草案查看和发布闭环，但将其放在次要位置
- 页面风格与现有 Ant Design 后台保持一致
- 提供稳定、可预测的加载、保存、轮询和异常反馈

### 3.2 非目标

- 不重做后端 CP-SAT 引擎
- 不修改现有排课接口协议
- 不引入全新设计系统或脱离现有后台风格的视觉语言
- 不在本轮实现复杂人工调课器、拖拽排课或高级本地校验

## 4. 设计原则

- 参数配置优先：主要工作流应围绕“选择年级 -> 编辑参数 -> 保存 -> 开始排课”
- 一屏高效编辑：尽量使用紧凑表格和行内编辑，而不是多层表单跳转
- 保持现有系统感：沿用现有后台页的留白、卡片和按钮体系
- 状态反馈明确：用户应始终知道当前是否已保存、是否正在求解、是否有失败项
- 前端不过度复制后端规则：只做最基础的格式和空值提醒

## 5. UI/UX 设计结论

本页已使用 `ui-ux-pro-max` 做设计检索，查询方向为“education school admin scheduling dashboard compact professional”与 React 表单/表格可访问性建议。

结合工具输出与本项目现有后台风格，本次采用以下折中方案：

- 保留“数据密集型后台工作台”方向
- 吸收工具在“高信息密度、明确状态、表单可访问性”上的建议
- 不采用工具给出的深色 claymorphism 视觉方案

原因：

- 用户已明确要求延续现有系统风格
- 当前项目整体为浅色 Ant Design 后台
- 排课管理页属于高频操作页，稳定性与熟悉感优先于强风格表达

## 6. 页面信息架构

页面采用“顶部总览 + 下方模块化配置”的混合工作台结构。

### 6.1 顶部工具条

工具条包含：

- 年级选择
- 刷新配置
- 保存全部
- 开始排课

交互要求：

- 顶部区域在页面滚动时保持易访问，视觉上可采用轻吸顶或固定页首操作区
- `保存全部` 和 `开始排课` 是主操作，位置保持稳定
- 当存在未保存变更时，顶部显示明显但不过度干扰的提示

### 6.2 总览卡片区

工具条下方展示 4 张轻量总览卡片：

- 课时计划数
- 任课安排数
- 教师约束数
- 锁定课时数

辅助信息：

- 最近一次草案状态
- 最近一次排课得分或结果摘要

作用：

- 用户无需切换页签即可快速判断当前年级配置是否完整
- 为“是否可以开始排课”提供心理预期

### 6.3 主体区页签

主体区使用 `Tabs` 组织功能，建议顺序如下：

1. 配置总览
2. 课时计划
3. 任课安排
4. 教师约束
5. 锁定课时
6. 排课草案

设计意图：

- 前 5 个页签服务参数配置主流程
- `排课草案` 保留闭环能力，但不抢占主要操作心智

## 7. 各模块设计

### 7.1 配置总览

用于汇总当前年级的配置完成情况和缺项提示。

展示内容：

- 当前年级
- 各配置模块条目数
- 明显缺项提示
- 快速跳转按钮

缺项示例：

- 尚未配置任课安排
- 尚未配置教师约束
- 尚未设置任何锁定课时

### 7.2 课时计划

采用紧凑表格批量编辑。

字段包含：

- 科目
- 周课时
- 每日上限
- 优先级
- 偏好时段
- 避免连堂
- 禁排时段

交互要求：

- 支持新增一行、删除一行
- 优先使用下拉框、数字输入框和开关
- `禁排时段` 允许以便于编辑的轻量文本格式录入，保存前转换为接口所需结构

### 7.3 任课安排

采用紧凑表格批量编辑。

字段包含：

- 班级
- 科目
- 教师

交互要求：

- 一屏展示多行，适合快速录入
- 提供新增、删除
- 使用下拉框避免手输

### 7.4 教师约束

采用紧凑表格批量编辑。

字段包含：

- 教师
- 每日最大课时
- 禁排时段

交互要求：

- 保持和课时计划一致的编辑体验
- 不做复杂前端规则推理，仅做基础格式提示

### 7.5 锁定课时

采用紧凑表格批量编辑。

字段包含：

- 班级
- 科目
- 教师
- 星期
- 节次
- 来源
- 备注

交互要求：

- 支持快速新增与删除
- 将“锁定”作为一类正式配置，而不是隐藏在草案区之后

### 7.6 排课草案

定位为次要但闭环必需模块。

展示内容：

- 当前任务状态
- 进度条
- 草案得分
- 草案摘要
- 草案明细表
- 发布按钮

交互要求：

- 点击“开始排课”后自动切换到该页签
- 支持查看明细与发布
- 当草案为空时有稳定空状态

## 8. 数据流设计

### 8.1 初始化

页面初始化时并行加载：

- 班级
- 科目
- 教师

### 8.2 年级切换

当年级切换时，并行加载：

- 课时计划
- 任课安排
- 课时覆盖
- 教师约束
- 锁定课时

并刷新当前草案相关状态。

### 8.3 编辑态

页面内部维护“接口原始值 + 前端编辑态”的转换层。

典型场景：

- `forbidden_periods` 在界面中以便编辑的文本或数组标签表示
- 提交保存前再转换为接口要求的二维数组

### 8.4 保存

`保存全部` 沿用现有 5 组保存接口。

要求：

- 页面只负责组织保存顺序与反馈
- 保存失败时不清空当前本地编辑态
- 保存成功后清除未保存提示

### 8.5 开始排课

沿用现有任务接口创建排课任务，并轮询任务状态。

成功后：

- 自动切换到 `排课草案`
- 刷新草案摘要和草案明细

失败后：

- 保留当前配置内容
- 在草案区或页顶展示后端返回的错误信息

## 9. 交互与反馈规则

### 9.1 加载

- 首屏基础数据加载失败时，页顶展示 `Alert`
- 提供重试按钮
- 局部加载用轻量 `Spin`，避免整页闪烁

### 9.2 保存

- 保存中禁用主按钮并显示加载态
- 保存成功给出统一成功提示
- 保存失败明确说明失败，不丢失输入

### 9.3 排课任务

- 排课中展示明确状态文案和进度条
- 轮询结束后自动停止
- 失败时优先展示后端错误文案，其次展示默认提示

### 9.4 空状态

以下场景都需要稳定空状态：

- 当前年级没有配置数据
- 当前没有草案
- 当前班级没有正式课表预览

## 10. 视觉规范

### 10.1 风格

- 延续当前系统浅色后台风格
- 使用 Ant Design 原生卡片、表格、标签、按钮、提示组件
- 避免引入过强装饰性视觉

### 10.2 密度

- 表格默认 `size=\"small\"`
- 卡片标题简洁
- 使用清晰分区和适度留白，而不是大面积装饰块

### 10.3 状态色

- 主操作：蓝色
- 成功：绿色
- 风险/提醒：橙色
- 失败：红色

### 10.4 可访问性

结合 `ui-ux-pro-max` React 指南，本页至少满足：

- 所有表单控件具备明确标签
- 对话框与确认框保持焦点管理稳定
- 不使用 placeholder 代替标签
- 所有主要交互状态具备清晰视觉反馈

## 12. 测试策略

前端验收优先覆盖以下行为：

- 页面可以稳定渲染主要模块
- 年级切换会触发配置加载
- 保存全部会调用现有保存流程
- 开始排课会进入轮询态
- 排课成功后自动切换到草案区
- 草案为空、加载中、失败三种状态有稳定 UI

如果当前仓库已有轻量前端回归脚本，应优先补充面向页面结构和核心流程的测试，而不是追求复杂 UI 单测。

## 13. 结论

本次排课管理页重写不追求“更炫”，而追求“更稳、更快录入、更符合学校管理员的配置工作流”。

最终交付应是一页基于现有 Ant Design 后台风格的排课配置工作台，重点服务以下主路径：

- 选择年级
- 批量配置排课参数
- 保存全部
- 发起排课
- 查看草案并完成发布闭环
